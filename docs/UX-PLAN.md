# DoodLive · 体验与流程设计计划（UX plan）

> 状态：草案 v1，2026-10-24。等 Gabriel 确认后再动代码。英文为仓库规范，这份先用中文写，因为是给你看的；定稿后我补英文摘要。

## 0. 为什么要这份计划

到目前为止我们是"功能驱动"：识别、贴色、模型、配音、标题……每一块都能跑，但**没有一条设计好的体验主线**：
什么时候该停下来等孩子，什么时候该自动往下走，界面怎么过渡，声音怎么让路，出错了怎么说。
这份计划先把这些定下来，之后每个功能都往这条主线上挂，而不是各自为政。

## 1. 一句话定义

**一个 5–9 岁的孩子，涂完一张纸，用手机一扫，30 秒内获得一个"我画的东西活了"的魔法时刻，并顺手认识了两个汉字。**
一切设计围绕"魔法时刻"的质量和到达它的速度。

## 2. 体验主线（孩子视角，一次完整使用 ≈ 3 分钟）

| # | 阶段 | 孩子看到 / 听到 | 系统在做 | 停还是走 | 退出条件 |
|---|---|---|---|---|---|
| 1 | **打开** | 标题 + 一个大按钮"扫一扫"。背景柔和动态（飘羽毛）。 | 预加载模型、音频；申请相机权限（只在按下按钮后） | **停**，等孩子按 | 按"扫一扫" / "看演示" |
| 2 | **引导** | 相机画面 + 虚线框 + 一句话"把整张纸放进框里"。四角找到时角上亮绿点，并有轻"叮"。 | 找标记 / ARCore 图像识别 | **走**：四角稳定 1.5 s 自动进入下一步，不需要按键 | 识别成功 → 3；30 s 没识别 → 显示"帮我一下"提示卡 |
| 3 | **魔法时刻**（最重要） | 白光一闪 → 画纸上泛起金色涟漪 → 天使从纸里升起（1.4 s）→ 羽毛飘落 → 合唱渐强 → 她说第一句话 | 烘焙贴图、放置、播放 Enter | **走**，全程不可打断（≤ 4 s） | Enter 结束 → 4 |
| 4 | **陪伴**（主场景） | 天使呼吸、眨眼、看向镜头；头顶标题（天使 / tiān shǐ）；底部 3 个大按钮：吹号角 · 读一读 · 再来一张 | Idle 循环；跟踪纸张 | **停**，等孩子互动。≥ 20 s 无操作时她主动说一句、招招手（最多 2 次，间隔 25 s） | 任一按钮 / 跟踪丢失 / 退后台 |
| 5 | **互动** | 吹号角：抬手 + 号角声 + 冲击环 + 说一句话。读一读：标题逐字放大、读汉字、读拼音、读英文。 | Blow 动画 / 朗读序列 | **走**，动作结束自动回到 4；动作期间按钮变灰，不叠加 | 动作结束 → 4 |
| 6 | **再来一张** | 淡出 → 回到 2，但引导文案变成"换一张纸试试" | 清理贴图、重置状态 | — | — |

**"停 / 走"的总原则：**
- 需要孩子**动手**的地方停（按按钮、对准纸）；系统**能自己判断**的地方走（识别稳定了就开始，动作做完就回待机）。
- 任何一次"走"都必须有**可见的进度反馈**（角点变绿、进度环、文字变化），不能让孩子不知道发生了什么。
- 所有自动推进都有**上限时间**，超时就给出一句具体的帮助（不是"失败"，是"把手机抬高一点"）。

## 3. 状态机（给工程用，网页版和 Unity 版共用同一套）

```
Boot ─► Home ─► Permission ─► Scan.Search ─► Scan.Locked(1.5s) ─► Reveal(≤4s) ─► Live.Idle
                                  ▲   │                                              │  ▲
                                  │   └─30s─► Scan.Help ─────────────────────────────┘  │
                                  │                                                     │
                           Live.Lost ◄──跟踪丢失 1.5s──┘   Live.Blow / Live.Read / Live.Greet ──┘
                                  │
                           Paused（退后台 / 来电）：音乐淡出 0.3s，恢复时淡入 0.6s，不重新识别
```

| 状态 | 进入时 | 期间 | 离开时 |
|---|---|---|---|
| Scan.Search | 状态栏滑入；音乐不响，只有环境底噪（极轻羽毛声） | 每 120 ms 检测一次；找到角点即时亮绿 | 角点连续稳定 1.5 s → Locked |
| Scan.Locked | 四角绿点 + 进度环 1.5 s | 若中途丢失 → 回 Search，进度清零 | 进度满 → Reveal |
| Reveal | 快门闪光 60 ms、合唱渐强、金色涟漪 | 不响应点击；**唯一**允许的操作是系统返回键 | Enter 动画结束 |
| Live.Idle | 音乐铺底 0.22；按钮淡入 300 ms | 20 s 无操作 → Greet（最多 2 次） | 按钮 / 丢失 / 后台 |
| Live.Blow / Read | 其他按钮禁用（灰 40%） | 音乐压到 40% | 动作结束 + 500 ms |
| Live.Lost | 天使停在最后位置、整体变暗 30%、状态栏"把纸拿回画面里" | 不消失、不复位 | 重新识别 → 立即恢复（淡入 300 ms） |
| Scan.Help | 卡片：三条带图的建议（抬高、对光、整张纸）+ "看演示" | — | 识别到 / 关闭卡片 |

## 4. 过渡与动效（统一的"手感"）

| 场景 | 动效 | 时长 | 缓动 |
|---|---|---|---|
| 页面 / 面板切换 | 交叉淡入淡出 + 轻微上移 12 px | 300 ms | ease-out |
| 状态栏文字变化 | 旧文字淡出、新文字从下方 8 px 滑入 | 200 ms | ease-out |
| 按钮出现 / 消失 | 缩放 0.9→1 + 淡入 | 220 ms，组内依次错开 40 ms | spring（轻） |
| 四角锁定 | 角点由白变绿 + 一次脉冲 | 150 ms | — |
| 天使登场 | 缩放 0→1（回弹 back-out）+ 旋转 360° + 上升 | 1400 ms | back-out |
| 标题出现 | 登场后 600 ms，从上方落下 + 轻回弹 | 500 ms | back-out |
| 跟踪丢失 | 变暗 30% | 400 ms | ease |
| 任何淡出退出 | 淡出 | 250 ms | ease-in |

规则：**UI 动效 ≤ 300 ms，角色动效 ≤ 1.5 s**；同一时刻最多一个"主角动效"；动效绝不阻塞输入超过 4 s（只有 Reveal 例外）。

## 5. 声音规则（已部分实现，这里定全）

优先级：**人声 > 音效 > 音乐**。
- 音乐铺底 0.22，有人声时压到 40%（已做）；Reveal 时合唱渐强盖过音乐。
- 人声**不叠加**：新的一句到来时，旧的一句淡出 150 ms 再放新的；同一句 6 s 内不重复。
- 每个按钮有自己的点击音（轻木鱼声），每次状态切换有对应提示音（锁定"叮"、丢失"嗒"低音）。
- 静音开关在右上角，记住选择；系统静音时只保留触感反馈。

## 6. 视觉设计系统（网页版和 Unity 版一致）

- **色板**：金 `#FFCF4A`（主按钮、高亮、标题）、墨 `#1B2028`、纸白 `#F7F4EC`、天空蓝 `#7CC4F0`、羽毛粉 `#FFB6D9`；状态色：绿 `#5DF59A`、红 `#FF6B6B`。
- **字体**：汉字学习用楷体（STKaiti → 上架前换思源宋体/楷体开源版）；UI 用无衬线粗体；拼音用带声调的同款。
- **按钮**：胶囊形，高 48–56 px，主按钮金色、次按钮半透明白；最多 3 个主按钮同屏；横屏时按钮靠右侧竖排。
- **安全区**：顶部状态栏避开刘海；底部按钮避开手势条（已处理）；Akita 横屏布局单独一套。
- **双语**：所有文字来自一张字符串表（zh / en），**中 / EN** 开关在右上角；汉字学习内容（田字格、拼音）在英文界面下仍然显示，因为那是内容不是界面。
- **指纹**：右下角 10 px 灰字（已做）。

## 7. 学习层（这是和别的涂色 AR 的差异点）

- 标题：汉字（田字格样式的 3D 字）+ 拼音 / 英文切换（已做）。
- **读一读**：点击标题或"读一读"按钮 → 逐字高亮、朗读汉字 → 拼音 → 英文；语速慢，可重复。
- 下一阶段：笔顺动画（田字格里一笔一笔写出来）、"跟我读"录音对比。

## 8. 错误与边界情况（每条都有中英文文案）

| 情况 | 表现 | 文案要点 |
|---|---|---|
| 没有相机权限 | 停在 Home，按钮变"去设置里允许相机" | 说明为什么需要相机，不收集照片 |
| 设备不支持 ARCore（部分 Akita 固件） | 退回"纸上模式"（只跟随纸，不做世界锁定） | 不要出现 "ARCore" 这个词 |
| 画面太暗 / 手机平放 | Scan.Help 卡片的第一条 | "抬高一点、对着亮的地方" |
| 扫到的不是我们的纸 | 维持 Search，不报错 | 30 s 后进 Help |
| 跟踪丢失 | Live.Lost | "把纸拿回来" |
| 退后台 / 来电 | Paused，音乐淡出 | 回来不重扫 |

## 9. 性能与设备

- 目标：Pixel 8 稳 60 fps，Akita 稳 30 fps，首屏 ≤ 2 s，Reveal 的贴图处理 ≤ 300 ms。
- 天使 116k 面可以；四个 3D 标题 27k–61k 面偏大，减面到 ≤ 12k；羽毛改成 LOD（远处合并）。
- 音频预加载，首次点击前不解码大文件。

## 10. 工程纪律（延续已有规则）

- 字符串表单一来源：`web/i18n.js` 与 Unity `L10n.cs` 由同一个 JSON 生成。
- 每个状态有一张"验收截图"：`scripts/qa-shots.sh` 通过 adb 依次把 App 带到每个状态并截图，放进 `docs/qa/<指纹>/`，提交前对比。
- 指纹核对（已做）、LESSONS（已做）。

## 11. 分期与顺序（建议）

| 里程碑 | 内容 | 产出 | 预计 |
|---|---|---|---|
| **M1 体验骨架** | 状态机、停/走规则、过渡动效、双语字符串表、声音优先级、错误文案、横屏 | 两个版本按同一张状态图运行；验收截图集 | 2–3 天 |
| **M2 魔法时刻打磨** | 登场特效（涟漪、羽毛、光柱）、场景（天空、云）、脸 v2、标题减面 | 对比视频 | 2–3 天 |

# Esther — music and sound effects

Generated by `tools/story/music_esther.py` from `assets/esther/timeline.json`. Do not hand-edit the audio files;
change the script and rerun it (about 50 s for everything):

```
python3 tools/story/music_esther.py                          # music + sfx + preview + the tables below
python3 tools/story/music_esther.py --skip-music --skip-sfx  # preview only (e.g. after new voice clips)
python3 tools/story/music_esther.py --only approach,sceptre  # re-render some cues, keep the others' manifest rows
python3 tools/story/music_esther.py --stems                  # also print per-stem levels (for balancing)
```

Needs `mido numpy scipy`, `fluid-synth`, `ffmpeg`, and macOS's General MIDI bank
`/System/Library/Components/CoreAudio.component/Contents/Resources/gs_instruments.dls` (same toolchain as
`tools/make_dg_music.py`). The tables between the `<!-- …:start/end -->` markers are rewritten by the script.

**After the timeline is re-timed (voices landing), just rerun the script.** It reads the timeline every run: cue
lengths come from the `music` spans, and every in-cue hit point is looked up by event, not by a fixed time
(see "Timeline hooks"). It asserts that every `music.cue` and `sfx.id` has a composer/synth and that every cue file is
at least span + 0.6 s long, so a new or renamed id fails loudly instead of shipping silence. Seeds are per cue / per
effect, so a rerun with the same timeline gives the same files, and changing one cue never changes another.

## Formats (CONTRACT section 7)

- `assets/esther/audio/music/<cue>.wav` and `audio/sfx/<id>.wav`: 44.1 kHz, mono, 16-bit PCM; a 96 kbps mono `.mp3`
  next to each (MP3 encoder padding adds ~0.03 s; use the WAV lengths for timing).
- Music: −20.0 LUFS integrated (EBU R128 via ffmpeg `ebur128`, iterative gain), true peak ≤ −1 dBTP.
- SFX: sample peak −3.0 dBFS. `gainDb` in `mix.json` is the recommended playback gain on top of that.
- Manifests: `audio/music/cues.json` (t, span, file length, bars, bpm, loudness, crossfade rule) and
  `audio/sfx/mix.json` (length, peaks, LUFS, `gainDb`).

## How the score is made

- Composed in code as MIDI, **one stem per instrument**, each rendered dry by FluidSynth (its reverb/chorus off),
  then mixed in numpy with per-stem gain, filters and reverb send into one shared convolution reverb (a synthesised
  hall impulse: early reflections, 2.3 / 1.8 / 0.9 s decay in lows / mids / highs). Mono throughout (Unity plays mono).
- Humanised: onset jitter (4–10 ms per part), velocity jitter, accent shaping, delayed mod-wheel vibrato on long
  melody notes, expression (CC11) swells on pads, qanun-style tremolo on long plucked notes, grace notes in the reed.
- Layering: qanun = koto + harp an octave below; reed lead = shakuhachi (breathy, ney-like) + soft oboe, or oboe +
  shanai in the climb; pads = slow strings + choir/oohs + contrabass.
- Each cue's tempo is stretched a few percent so a whole number of bars exactly fills its span: cadences land on the
  next cue instead of being cut mid-phrase. Phrases are laid out backwards from the cue end so the cue always ends on
  the phrase's last bar, with an intro bar or two when there is room.
- All themes are original. Modes: D Dorian (palace), D minor (Haman, Mordecai), D Phrygian dominant / Hijaz
  (tension, approach, truth), D major (sceptre, celebration), D Mixolydian (banquet). Everything stays on D so any
  crossfade is in key.

## Sound effects

All synthesised (numpy/scipy), no samples. Bells/glints/glass are decaying inharmonic partials with beating; the
`gasp` and `cheer` voices are a jittered glottal source plus breath noise through **time-varying formant filters**
(STFT), several people layered a few milliseconds apart and placed in a synthetic room so they read as people in a
hall rather than a synth tone.

## Known limits

- Checked by measurement (ffmpeg ebur128), spectrograms and the event map, **not by ear** (the script was written
  unattended). Listen first to: `gasp`, `cheer` (synthetic voices are the weakest link), the shakuhachi/shanai reed
  colour in `tension` / `truth`, and whether the timpani heartbeat in `approach` is too much.
- The General MIDI bank has no qanun, oud, ney or darbuka; they are approximated (koto + harp, nylon guitar,
  shakuhachi + oboe, congas/bongos). Replace any cue or effect with a recording later: same id, same format.
- Cue lengths are tied to the timeline spans. If Story moves a `music` entry, rerun the script.
